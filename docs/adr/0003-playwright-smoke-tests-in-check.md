# ADR-0003: Playwright smoke-тесты в корневой проверке

- Статус: принято; состав webServer уточнён в ADR-0004
- Дата: 2026-11-21

## Контекст

У клиента нет тестовой инфраструктуры, а корневой `pnpm check` проверяет только форматирование, линт, серверные тесты и сборку. Первый пользовательский путь — главная → основной призыв к действию → страница записи. Это единственный сценарий, который можно проверить end-to-end уже сейчас.

## Решение

Добавляем `@playwright/test` и smoke-тест, который проверяет открытие главной, наличие основного призыва к действию, переход по нему на `/book` и отображение заглушки страницы записи.

- Используем только Chromium.
- Корневой `pnpm test` запускает серверные тесты и Playwright; `pnpm check` уже включает `pnpm test`, поэтому отдельная команда для CI не нужна.
- Playwright сам поднимает клиентский dev-сервер (конфигурация `webServer`).
- Конфигурация и e2e-тесты находятся в пакете `client`, но запускаются и корневыми командами.
- В `.github/workflows/ci.yml` перед `pnpm check` добавляется отдельный шаг установки Chromium с системными зависимостями. `hexlet-check.yml` не изменяется.

## Рассмотренные альтернативы

- **Не добавлять клиентские тесты сейчас** — отклонено: переход между экранами — главный результат этапа, его нужно защитить от регрессий.
- **Vitest + React Testing Library** — отклонено: компонентные тесты не проверяют реальный URL, историю браузера и фактическую навигацию.
- **Playwright только локально** — отклонено: тогда CI не заметит поломку основного сценария.

## Последствия

- `pnpm check` требует установленного браузера Chromium: локально его ставят один раз, в CI — отдельным шагом.
- Проверка становится медленнее; набор вырос: к home smoke добавлены другие e2e, а полный гостевой сценарий определён в ADR-0004.
- Тестовая инфраструктура клиента появляется раньше остальных его тестов; новые e2e-сценарии добавляются в тот же набор.
