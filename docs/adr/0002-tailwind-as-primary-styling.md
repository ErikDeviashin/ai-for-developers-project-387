# ADR-0002: Tailwind CSS как основной способ оформления клиента

- Статус: принято
- Дата: 2026-11-21

## Контекст

Сейчас клиент оформлен одним рукописным `index.css` с общими правилами для `main`, `h1` и `p`. Впереди — календарь, формы бронирования и интерфейс владельца. Без выбранного подхода стили начнут расползаться между глобальным CSS и компонентами.

## Решение

Tailwind CSS (v4, через плагин `@tailwindcss/vite`) — основной способ оформления клиентского интерфейса. Разметка описывает внешний вид утилитами Tailwind. Отдельную UI-библиотеку не добавляем. Рукописный компонентный CSS и CSS-модули не используем как основной подход.

## Рассмотренные альтернативы

- **Продолжать рукописный CSS** — отклонено: глобальные селекторы плохо масштабируются на календарь и формы, а решения о внешнем виде становятся неявными.
- **CSS-модули** — отклонено: больше файлов и переключения контекста, нет готовых токенов отступов, цветов и адаптивных вариантов.
- **UI-библиотека** — отклонено: преждевременно, задаёт чужой визуальный язык и лишние зависимости.

## Последствия

- Появляется сборочная зависимость Tailwind; существующий `index.css` заменяется импортом Tailwind и, при необходимости, небольшим слоем базовых стилей.
- Повторяющиеся наборы утилит стоит выносить в компоненты, а не в глобальные классы.
- Визуальные решения фиксируются в разметке и проходят ревью вместе с ней.
