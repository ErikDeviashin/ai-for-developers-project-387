# ADR-0004: Playwright e2e на реальных Fastify и Vite

- Статус: принято
- Дата: 2026-11-23

## Контекст

ADR-0003 добавил Playwright и smoke-тест, в котором Playwright поднимал только клиентский dev-сервер. После появления бронирования один браузерный сценарий должен проверять полный гостевой путь: выбор типа, даты и слота, отправку данных и появление встречи у владельца. Проверять его на заглушках API или только на клиенте недостаточно: ошибки контракта, серверной валидации и совместной работы Fastify и Vite останутся незамеченными.

## Решение

Playwright поднимает и реальный Fastify-сервер, и реальный Vite dev-сервер.

- Сервер запускается через `pnpm --filter server start:e2e` на `127.0.0.1:3000`; клиент — через `pnpm exec vite --port 5173 --strictPort`.
- E2E-сервер использует in-memory SQLite и фиксированные внедряемые часы (`now`); production-вход по-прежнему использует реальное время и файловую БД.
- Клиент обращается к API по относительным URL, Vite проксирует запросы; CORS не добавляется.
- Запускается один worker, `reuseExistingServer: false`, только Chromium.
- API используется только для подготовки данных и вычисления ожидаемых значений; тип, дату и слот выбирает браузер через интерфейс. Финальная проверка — прямой переход на `/owner`, который читает встречи через реальный `GET /meetings`.

## Рассмотренные альтернативы

- **Только Vite с подменой API** — отклонено: не проверяет реальный контракт и серверное поведение, ради которых и существует сквозной сценарий.
- **Постоянная файловая БД и реальные часы** — отклонено: тест зависел бы от текущей даты и оставлял бы состояние между запусками.
- **`reuseExistingServer: true`** — отклонено: случайный уже запущенный сервер или клиент мог бы дать устаревшее состояние и скрыть поломку.
- **Несколько workers** — отклонено: сервер и in-memory SQLite общие для набора, параллельный запуск сделал бы сценарии недетерминированными.

## Последствия

- `pnpm check` и `pnpm test:e2e` требуют свободных портов 3000 и 5173 и запускают оба приложения.
- Сквозной сценарий проверяет совместную работу клиента, API и SQLite, а не только навигацию клиента.
- Даты в e2e фиксированы внедрёнными часами сервера; клиентское «Сейчас» по-прежнему зависит от часов браузера.
